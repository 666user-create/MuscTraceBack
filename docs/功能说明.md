# MusicTraceBack 功能说明

> 一句话:给歌单做"身份追溯"。粘贴歌单链接,识别每首歌的真实身份,
> 跨网易云 / QQ 音乐 / 酷狗找出所有版本并按置信度 + 热度展示 Top 3。

---

## 它解决什么问题

歌曲在音乐平台上下架、被替换成翻唱/Live 是常事。本工具回答三个问题:

1. **这首歌原来是什么?**(原唱、原专辑、原始时长)
2. **它现在还能在哪听?**(跨三平台找出可用版本)
3. **歌单还健康吗?**(体检报告:健康分 + 问题曲目清单)

## 核心概念

| 概念 | 说明 |
|---|---|
| **身份(Canonical Track)** | 一首歌的"真实身份":歌名 + 歌手 + 规范化后的匹配键 |
| **版本(Platform Version)** | 同一身份在某个平台上的具体条目,标注版本类型 |
| **版本类型** | `ORIGINAL` 原版 / `LIVE` 现场 / `COVER` 翻唱 / `REMIX` 重混 / `INSTRUMENTAL` 伴奏 / `OTHER` |
| **置信度** | 身份与版本匹配的把握程度:`HIGH` / `MEDIUM` / `LOW`,由打分引擎根据标题、歌手、时长、专辑等证据综合判定 |
| **条目状态** | `NORMAL` 正常 / `REPLACED` 被替换(如原版换成翻唱)/ `DELISTED` 已下架 |

## 功能清单

### 1. 三平台歌单注入
- 支持粘贴**网易云 / QQ 音乐 / 酷狗**的歌单分享链接(或纯数字 ID),自动识别平台并解析全部曲目。
- 注入是**异步**的:接口立即返回,后台单线程逐条处理,页面实时显示进度条,可离开页面。
- **断点续跑**:处理进度逐条持久化,中途关掉应用,重启后自动继续未完成的部分。

### 2. 身份解析(零请求建档)
- 来源平台的歌单数据直接用于本地建档,不额外发请求,正常曲目全部高置信。
- 标题/歌手经 `TextNormalizer` 规范化(去括号注释、空白折叠、大小写与全半角归一),提升跨平台匹配率。

### 3. 跨平台版本发现(Top 3)
- 每首歌在**其他两个平台**搜索候选版本,由 `VersionScorer` 打分:
  标题相似度、歌手匹配、时长差、专辑、热度等多证据加权。
- 每平台取分数最高的 3 个版本,按"置信度 → 热度"排序展示,并计算平台内热度百分位。

### 4. 下架追查与替换检测
- 歌单里找不到原版的曲目标记为**已下架**,展示其他平台的可用版本;
- 检测到歌单里实际放的是翻唱/Live/Remix 时标记为**被替换**,一眼看出歌单"变味"的地方。

### 5. 用户确认兜底
- 对"疑似/待确认"曲目,一键确认"是原版"或指定版本类型,结果持久化,越用越准。

### 6. 体检报告
- 每个歌单一份:健康度评分(0-100)+ 状态分布 + 置信度分布 + 问题曲目清单。

### 7. 平台友好与自我保护(内置,无需配置)
- 同平台请求限流(默认最小间隔 800ms),降低触发平台风控概率;
- 触发风控(406/"操作频繁")自动冷却该平台,期间跳过,冷却结束自动恢复;
- 某平台接口连续失败会"断路"(默认 3 次失败断路 120 秒),单平台挂掉不拖垮整体;
- 处理进度逐条落库,任何中断都不丢进度。

## 使用流程

1. 打开 http://localhost:8080,粘贴歌单分享链接;
2. 点"开始追溯"——立即返回,页面显示后台处理进度;
3. 完成后查看体检报告与曲目列表,点击"查看版本"展开各平台 Top 3;
4. 对"待确认"曲目点击"确认是原版"完成兜底;
5. 点击版本跳转链接可直接到平台官方页面收听。

> 200 首歌单约 2-3 分钟后台跑完;遇平台风控自动暂停,恢复后自动继续。

## REST API

统一响应包:`{ "code": 200, "data": ..., "message": ... }`(错误时 code 为对应 HTTP 状态码)。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查(应用状态 / 数据库 / 时间) |
| POST | `/api/playlists/import` | 注入歌单,入参 `{"url": "歌单链接"}`,立即返回歌单摘要 |
| GET | `/api/playlists/{id}/progress` | 处理进度(状态 / 已处理数 / 百分比) |
| POST | `/api/playlists/{id}/resume` | 手动续跑(重启挂起的歌单) |
| GET | `/api/playlists/{id}` | 歌单详情(条目列表) |
| GET | `/api/playlists/{id}/tracks/{entryId}` | 单曲详情(含跨平台版本列表) |
| POST | `/api/playlists/tracks/{entryId}/confirm` | 用户确认,入参 `{"versionType": "ORIGINAL"}` |
| GET | `/api/playlists/{id}/report` | 体检报告 |

## 技术栈与架构

- **Java 17 + Spring Boot 4.1 + JPA + H2(file 模式,零外部依赖)**
- 前端零构建工具链:原生 HTML/CSS/JS + fetch 轮询
- 适配层:`PlatformAdapter` 接口 → 网易云 / QQ / 酷狗三个实现,**新增平台 = 新增一个实现类**
- 打分引擎 `VersionScorer` 与文本规范化 `TextNormalizer` 为纯函数,可独立测试
- 测试 78 个,平台接口用 MockWebServer 离线模拟,不依赖真实网络

```
Web 层    静态前端 + REST API(PlaylistController / HealthController)
应用层    PlaylistInjectionService / InjectionProcessor(异步编排)
          EntryProcessingService(单条事务)/ IdentityResolutionService
          VersionDiscoveryService / UserConfirmationService
领域层    实体 + TextNormalizer + VersionScorer
适配层    PlatformAdapter → NetEase / QQ / Kugou
基础设施  H2 / SearchCache / HttpFetcher(限流·冷却·断路)
```

## 已知限制

- 平台接口为逆向的公开元数据接口,随时可能变更;各平台适配器独立隔离,单平台失效不影响其他平台。
- 短时间大量请求可能触发平台风控,工具会自动冷却等待;如频繁触发可调大 `music.http.min-interval-ms`。
- 只读取公开的曲目元数据(歌名/歌手/时长/专辑),不下载、不播放、不破解任何音频或 DRM。
